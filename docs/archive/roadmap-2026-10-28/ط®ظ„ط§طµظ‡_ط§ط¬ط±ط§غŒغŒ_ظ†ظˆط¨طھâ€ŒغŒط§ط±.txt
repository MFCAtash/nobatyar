نوبت‌یار — خلاصه اجرایی نقشه‌راه توسعه
نسخه 1.0 — ۲۸ اکتبر ۲۰۲۶

هدف: پلتفرم فارسی RTL برای نوبت‌دهی و مشاوره پزشکی با نقش‌های بیمار، پزشک و ادمین.

پشته گزارش‌شده: pnpm/Turborepo، Next.js 14، NestJS/Prisma، PostgreSQL 16، Redis، MinIO و packages/shared.

وضعیت: فازهای ۰ تا ۵ در تحلیل مبنا تحویل‌شده گزارش شده‌اند، اما build/test/staging باید اجرا و ثبت شود. کد جدید احراز هویت با schema و تست‌ها ناسازگار است؛ بنابراین گام بعدی فاز ۵.۵ است، نه شروع مستقیم فاز ۶.

اولویت فوری:
۱) همگام‌سازی Prisma schema و migration با password/MFA/tokenVersion.
۲) اصلاح تست token و افزودن تست password/TOTP/recovery/revocation.
۳) تکمیل UI MFA ادمین و مسیر mfa_required.
۴) تصمیم قطعی OTP-only یا OTP+password.
۵) به‌روزرسانی env/docs/threat model.
۶) سبز شدن lint/typecheck/unit/integration/build و تست sandbox درگاه.

پس از آن: فاز ۶ اعلان/فایل/چت؛ فاز ۷ ویدئو LiveKit؛ فاز ۸ پرونده سلامت/triage/نظر دوم با بازبینی بالینی و حقوقی؛ فاز ۹ KMS/backup/restore/monitoring؛ فاز ۱۰ بتای بسته.

قاعده اصلی: هر ویژگی باید migration، API contract، مجوز/consent، UI، تست و مستندات داشته باشد. داده سلامت نباید وارد log/analytics شود. رزرو، پرداخت و refund باید idempotent و قابل ممیزی باشند.

محدودیت: build و تست در تحلیل مبنا اجرا نشده بود؛ Gateها باید در محیط واقعی راستی‌آزمایی شوند.
