# فاز ۴ — یکپارچه‌سازی فرانت‌اند (`apps/web`)

## وضعیت پروژه
فاز ۰ تا ۳ (زیرساخت، دیتابیس/امنیت، احراز هویت، چرخه‌ی نوبت) **تحویل شده**؛ این بسته **فاز ۴** است. بعدی: فاز ۵ پرداخت، ۶ پیام‌رسانی و فایل، ۷ ویدئو، ۸ پرونده‌ی سلامت/triage، ۹ سخت‌سازی، ۱۰ بتا.

## چه ساخته شد
اپ Next.js 14 (App Router، TypeScript، RTL فارسی) که مستقیم به API واقعی وصل است:

| مسیر | کار | API |
|---|---|---|
| `/` | جستجوی پزشک (نام + تخصص، debounce، صفحه‌بندی) | `GET /doctors`, `/specialties` |
| `/login` | ورود با OTP (شمارنده‌ی ارسال مجدد، ارقام فارسی) | `POST /auth/otp/*` |
| `/onboarding` | نام + رضایت‌نامه‌ها | `PATCH /me/profile`, `POST /me/consents` |
| `/doctors/[id]` | پروفایل، انتخاب روز (۷ روز، تقویم جلالی) و ساعت، رزرو | `GET /doctors/:id[/slots]`, `POST /appointments` |
| `/appointments`, `/appointments/[id]` | نوبت‌های بیمار، جزئیات، لغو با برآورد بازپرداخت، گزارش غیبت | `GET/POST /appointments/*` |
| `/doctor` | صف نوبت‌ها با اقدام سریع (تأیید، شروع، پایان، لغو، غیبت) | همان |
| `/doctor/schedule` | تنظیمات، برنامه‌ی هفتگی، تخصص‌ها، مرخصی | `/doctors/me/*` |
| `/admin/verifications` | تأیید/رد درخواست پزشک | `/admin/doctor-verifications/*` |

## تصمیم‌های فنی
- **Access token فقط در حافظه**؛ refresh token در کوکی HttpOnly. API از طریق `rewrites` همین مبدأ پروکسی می‌شود (`/api/v1/*`) تا کوکی `SameSite=Strict` بدون مشکل CORS کار کند.
- **refresh ایمن:** چون سرور استفاده‌ی مجدد از refresh token را سرقت می‌داند، کلاینت سه لایه دارد: single-flight داخل تب، قفل Web Locks بین تب‌ها و اشتراک توکن تازه با BroadcastChannel (تست‌شده: دو تب ⇒ فقط **یک** درخواست refresh). خطای موقت شبکه/سرور کاربر را خارج نمی‌کند؛ فقط ۴۰۱/۴۰۳ از refresh.
- **تاریخ و ساعت:** همه‌چیز با `Intl` و منطقه‌ی `Asia/Tehran` و تقویم جلالی (بدون وابستگی)؛ لبه‌ها تست شده‌اند (سال کبیسه‌ی ۱۴۰۳، مرز روز ساعت ۲۰:۳۰ UTC). ورودی datetime-local مرخصی به‌صورت «وقت تهران» تفسیر می‌شود.
- **مبالغ:** API ریال است؛ UI تومان نشان می‌دهد (`BigInt`، بدون خطای ممیز شناور).
- **امنیت UI:** پیام‌های خطا فارسی و بدون جزئیات فنی؛ `safeNext` جلوی open-redirect را می‌گیرد؛ هدرهای امنیتی و CSP پایه در `next.config.mjs`؛ فونت خودمیزبان (`@fontsource-variable/vazirmatn`) به‌جای Google Fonts. محافظ مسیر سمت کلاینت فقط UX است؛ امنیت واقعی با Guard و RLS در API.

## ⚠️ تفاوت‌های عمدی با پروتوتایپ‌های HTML
1. **ورود فقط با OTP است؛ رمز عبور/ثبت‌نام با رمز/فراموشی رمز پیاده نشد.** پروتوتایپ `auth-5.html` این‌ها را دارد ولی بک‌اند (فاز ۲) عمداً بدون رمز عبور است (سطح حمله‌ی کمتر، بدون ذخیره/بازیابی رمز). اگر رمز لازم دارید باید به‌عنوان تصمیم محصول تعیین تکلیف شود.
2. **کد OTP در پروتوتایپ سمت کلاینت ساخته و در toast نشان داده می‌شد** (شبیه‌سازی). اینجا کد فقط سرور می‌سازد و پیامک می‌شود.
3. **فرم کارت بانکی (شماره کارت/CVV) در `doctor-profile-8.html` پیاده نشد و نباید بشود:** اطلاعات کارت هرگز نباید از سرور/فرانت ما عبور کند. پرداخت در فاز ۵ با **ریدایرکت به درگاه** است. تا آن زمان نوبتِ دارای هزینه در وضعیت «در انتظار پرداخت» با شمارنده‌ی نگه‌داری می‌ماند.
4. `localStorage` به‌عنوان دیتابیس (اعلان‌ها، لاگ پیامک، کاربر) حذف شد؛ همه‌چیز از API می‌آید.

## هنوز پوشش داده نشده (نیازمند API فازهای بعد یا تصمیم محصول)
مقایسه‌ی پزشکان، لیست انتظار، مرکز اعلان‌ها و تنظیمات پیامک، اعضای خانواده برای رزرو، تور راهنما، نمودار حرارتی/درآمد پزشک، SOAP و نسخه‌نویسی، نظر دوم، triage، پرونده‌ی سلامت، چت و ویدئو (صفحات `chat`/`video-call` در فاز ۶ و ۷)، و **پنل ادمین کامل** (فقط تأیید پزشک است).

## ظاهر
UI با **توکن‌های `design-system.pdf`** (پالت تیره/روشن، تایپوگرافی، شعاع‌ها) و کامپوننت‌های تازه ساخته شد؛ «پیکسل‌به‌پیکسل» مثل پروتوتایپ‌ها نیست (حباب‌های متحرک، DNA، tilt، reveal-on-scroll هنوز نیامده‌اند). پروتوتایپ‌ها هر کدام CSS اختصاصی و بزرگ دارند و کلاس‌های مشترک تقریباً ندارند؛ پورت دقیق باید صفحه‌به‌صفحه (فاز ۴ب) انجام شود.

## راه‌اندازی
```bash
pnpm install
# API: در .env این‌ها را بگذارید (برای بررسی CSRF و IP واقعی کلاینت پشت پروکسی Next)
#   CORS_ORIGINS=http://localhost:3001
#   TRUST_PROXY_HOPS=1
pnpm --filter @nobatyar/api dev            # پورت ۳۰۰۰
pnpm --filter @nobatyar/web dev            # پورت ۳۰۰۱ — API_URL پیش‌فرض http://localhost:3000
```
تست: `pnpm --filter @nobatyar/web test` (کلاینت API، قالب‌بندی جلالی/تهران، پیام‌ها). برای دیدن یک جریان کامل: `pnpm --filter @nobatyar/api db:seed`، با شماره‌ی `09120000002` (بیمار seed) وارد شوید؛ با `SMS_PROVIDER=console` کد در لاگ API چاپ می‌شود.

## اصلاحات ادامه‌ی فاز ۴ (۱۴۰۵/۰۷/۲۱)
- **خروج ناخواسته‌ی موقت:** `bootstrap()` حالا سه‌حالته است (`ok`/`denied`/`error`) و `refreshMe` فقط با ۴۰۱/۴۰۳ کاربر را «مهمان» می‌کند. خطای شبکه/سرور وضعیت `error` با دکمه‌ی «تلاش دوباره» می‌دهد.
- **خروج هم‌زمان بین تب‌ها:** logout در یک تب با BroadcastChannel به تب‌های دیگر می‌رسد (بدون درخواست اضافه به سرور).
- **رقابت ریدایرکت بعد از ورود:** فقط یک جا (effect صفحه‌ی ورود) ریدایرکت می‌کند؛ مسیر onboarding برای کاربر بدون نام هم همان‌جاست.
- **دسترس‌پذیری:** تله‌ی فوکوس و `aria-labelledby` در Modal؛ فقط یک لینک `aria-current` در هدر (`/doctor` در برابر `/doctor/schedule`)؛ حذف نقش نامعتبر `tab` از انتخاب روز.
- تست‌های تازه: bootstrap سه‌حالته، logout بین تب‌ها. ۱۹ تست منطقی (api/format) محلی با موفقیت اجرا شد.
- ⚠️ **اجرا نشد:** `pnpm build`، `typecheck`، lint و تست‌های integration (به نصب وابستگی و Docker نیاز دارند). فقط بررسی نحوی فایل‌ها انجام شده.
