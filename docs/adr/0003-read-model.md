# ADR 0003 — Read Model مبتنی بر view بهجای جدول materialized

- وضعیت: پذیرفتهشده (فاز ۲۴)
- تاریخ: ۱۴۰۵/۰۹/۰۱

## زمینه
داشبورد پزشک نیاز به آمار روزانه (ویزیت، غیبت، لغو، درآمد) دارد. اجرای تجمیع سنگین روی جداول تراکنشی در هر درخواست، Latency را بالا میبرد.

## تصمیم
- view `v_doctor_daily_stats` با گزینهٔ `security_invoker = true` ساخته میشود تا RLS جداول پایه اعمال شود.
- سرویس `ReadModelService` فقط از این view میخواند و محاسبات ساده را در حافظه انجام میدهد.
- در مقیاس بالاتر، view به materialized view با refresh تدریجی توسط maintenance worker تبدیل میشود.

## پیامدها
- (+) بدون data duplication و بدون ضرورت job تازه؛ همیشه تازه است.
- (+) RLS بهطور خودکار اعمال میشود.
- (−) برای dataset های 매우 بزرگ نیاز به ایندکس یا materialization خواهد شد.
- (−) view نمیتواند از RLS عبور کند؛ بنابراین نقش اپ باید مجوز لازم را داشته باشد.
