# مدل تهدید نوبتیار (نسخه‌ی پیش‌نویس ۰.۱)

> روش: STRIDE روی نمودار جریان داده. وضعیت: **نیازمند تأیید** مسئول امنیت و مالک محصول.

## ۱. دارایی‌ها (Assets)
| کد | دارایی | طبقه |
|---|---|---|
| A1 | پرونده‌ی سلامت، نتایج triage، نظر دوم | HEALTH |
| A2 | پیام‌های چت پزشکی و پیوست‌ها | HEALTH |
| A3 | هویت کاربر (نام، موبایل، کدملی در صورت نیاز) | PERSONAL |
| A4 | نوبت‌ها و سابقه‌ی مراجعه | HEALTH |
| A5 | توکن‌ها و نشست‌ها، کلیدهای رمزنگاری | PERSONAL/سرّی |
| A6 | تراکنش‌های پرداخت (شناسه و وضعیت) | PERSONAL |
| A7 | مدارک احراز پزشک | PERSONAL |
| A8 | لاگ ممیزی (یکپارچگی آن) | داخلی |

## ۲. بازیگران
بیمار، پزشک، ادمین، مهاجم خارجی، کاربر مخرب احراز‌شده (بیمار/پزشک)، فرد داخلی (توسعه‌دهنده/ادمین زیرساخت)، سرویس‌های ثالث (درگاه، پیامک).

## ۳. مرزهای اعتماد
1. مرورگر/اپ ⇄ API (اینترنت)
2. API ⇄ PostgreSQL / Redis / MinIO (شبکه‌ی داخلی)
3. API ⇄ سرویس‌های ثالث (درگاه پرداخت، پیامک، LiveKit)
4. ادمین ⇄ پنل مدیریت

## بخش ۵: مانیتورینگ، PWA، Push، hook های تست
| تهدید | کنترل |
|---|---|
| نشت داده‌ی بیمار به Sentry | `scrubEvent` (allowlist/denylist/الگو، fail-closed)؛ بدون DSN خاموش؛ semgrep روی `sendDefaultPii`/init بدون scrub؛ فقط ۵xx گزارش می‌شود |
| cache شدن داده‌ی سلامت در دستگاه (SW) | SW فقط allowlist ی استاتیک؛ `/api`, HTML, callback پرداخت هرگز؛ تست مرورگری محتوای Cache Storage |
| نشت اطلاعات از اعلان صفحه‌ی قفل / سرویس Push | متن عمومی، URL نسبی؛ `assertSafePayload`؛ بدون نام/تخصص/دلیل |
| سرقت/سوءاستفاده از اشتراک Push | endpoint/کلیدها رمزنگاری‌شده، RLS، سقف هر کاربر، حذف خودکار |
| باز ماندن hook ی OTP در production | سه لایه: ثبت مشروط ماژول، خطای راه‌اندازی config، throw در سازنده‌ی کنترلر؛ تست‌شده |
| open redirect از کلیک اعلان | `safeUrl` فقط مسیر نسبی (`sw-policy.js`، تست‌شده) |
